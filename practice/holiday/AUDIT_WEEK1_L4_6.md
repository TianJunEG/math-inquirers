# Independent audit: holiday online practice, week 1 (lessons 1 and 2), Levels 4, 5 and 6

Branch `claude/great-fermi-1hv4vc`. Read-only audit (only this file was added). Method: I built all six lessons (`build_holiday.py pN N`), served each `dist`, drove them in Chromium (390 px and 900 px, light and dark), made the server keys (`make_keys.py holiday pN N`) and ran `practice/submit/mark.js`. I did not run `test_holiday.py` (it overwrites the tracked `proof/` PNGs).

Verdict: **correct answers and marking are sound, and the flow works, but not ready to go live as is.** All 223 items agree with my hand solutions. There is no wrong key, no wrong worked solution, no layout break at 390 px, no run-code-in-page risk and no private-source text. The problems are in the answer-matching rules (a few wrong answers accepted, many natural right answers refused), several hints and examples that give the answer away, a likely iPhone keypad problem, and the privacy line on the page. None needs a rebuild of the lessons; most are fixes in the shared `sheet.js` / `mark.js` or in a few strings.

## 1. Hand-solved against the printed workbook
I solved every item from the question text only, before looking at any stored answer, then compared automatically (non-text items) and by hand (text items). One disagreement, my own slip (P4 L2 T3, 17 250, 19 500, 21 750: the next two are 24 000 and 26 250, stored is right). Extra independent code second checks: B1 (all bracketings of 1+2×3+4×5+6: maximum 231), B2 (smallest 6 953 487), every single-bracket placement for P5 L1 5a/5b/5c/A2a/A2b (each target has exactly one placement, so the one accepted bracket form is the only right one), P4 L2 I3, P4 L2 G6 (30 261 is the only fit), P6 L2 I1 (28 pairs, 4 prime sums), lockers, Goldbach lists. Also read all hints and worked steps (about 223 items): no wrong statement found. Every printed workbook question, Think harder A/T and Go further item is present (P6 "Think harder" is `lesson.th` = stretch plus the moved item, as STATUS says).

Meaning changes or lost information (printed vs online):
- **Medium** P5 L2 B2: printed "How can the pizzas be cut?"; online asks for the two unit-fraction splits and says "Find the two ways", which also tells the child there are exactly two. The "cut 4 pizzas into thirds ..." part survives only in the solution.
- **Low** P5 L1 6a: printed "circle each one"; online "type each one that rounds to 2 500 000 ... for example 2499500, 2500000". The example is two of the three answers.
- **Low** P4 L1 Q2(a): the printed table has 4 rows of 10 pre-filled; online says "One way is 4 rows of 10 ... type the number of rows for every way" and 4 must be typed. Q1(a) says "1 × 48 is done for you, type the others", so a child can read Q2(a) either way and gets no feedback on why 4 is needed.

- **Low** P5 L1 1(b) "the digit 4 stands for" gives no hint that a number is wanted; "four hundred thousand" is marked wrong (only 400000, 400 000, 400,000 pass).
- **Low** Splitting a multi-part question puts earlier answers in later questions: P4 L1 6(a) step 2 and 3 print 36, 48, 60 and 36, 60; P6 L1 3(b) "101 is a term. Which term?" gives away 3(b) (Yes); P6 L2 3(b) why says "The code says 2", which is the answer to 3(b).

## 2. Accepted-answer sets
Ran `mark.js` on about 20 variants per item (all 187 auto items: 65 number, 42 boxes, 36 list, 24 choice, 20 text) plus about 200 hand-picked strings for the 20 text items. The client (`sheet.js`) and server (`mark.js`) agreed on every one (section 6).

Works as expected: space-grouped and comma-grouped numbers in numbers, boxes and lists ("12 500", "12,500"), padding, lists with commas, spaces, semicolons, "and", trailing comma, any order for unordered lists, wrong-order rejected for ordered lists, `$120`, x / * / × for brackets, `-` and `−` inside text, upper case. Near-miss values (+1, −1, ×10, one list item changed, one extra, one missing, duplicated) are marked wrong. The known gap (a comma typed inside one number in a list) did not bite any list in these six lessons: no list has a 1 to 3 digit entry directly before a three-digit entry written without a space.

Problems:
- **Medium** Wrong answers marked right (text items, because `normText` turns every `-`, `−`, `–` into a space and then deletes spaces): `-0.5` for P6 L1 T4b difference, `-0.5n` for the rule, `-1/2` for P5 L2 A2, `-1/4` for 3(c), `-2/3` for A4; `(6+4)×52` for P5 L1 5(a) and `6+4×(52)` for 5(b) (a dropped minus sign). `1 1/2` is marked right for P5 L2 6(a) (answer 5 1/2) because "1 1/2" and "11/2" become the same string. Fix: do not strip a minus before a digit, and keep a space between a whole number and a fraction.
- **Medium** Natural right answers refused: every bracket item (P5 L1 5a/b/c, A2a/b) rejects the whole statement with the result, e.g. `(6+4)×5−2=48` (the printed line ends "= 48", so children will type it); also `5×(6+4)−2`, `((6+4)×5)−2`, en dash `–`, `·`. Fix: ignore a trailing "= number".
- **Medium** Number answers with a unit or full stop are refused: `301 sticks`, `10 factors`, `20 min`, `29.`, `29.0` (all 65 number items; 42 box items refuse `20 min` and `6:20` where the frame already prints "6:"). Only P5 L2 5(a)/(b) say "type the number of dollars". Fix: either say "type the number only" under every number input or strip a trailing unit word.
- **Low** Unicode minus `−4` and `–4` refused in the P6 L1 2(b) box (the printed workbook uses `−`); `(-4)`, `minus 4` refused.
- **Low** Words refused: `five eighths`, `three quarters`, `half`, `a quarter`, `25%`, `5 and a half`, `5½`, `1/2 of the pizza`, `0.67` (these are reasonable for 10 to 12 year olds; the page says "type a fraction", so only a Low).
- **Low** P5 L2 4(b)(1) accepts only `2/3`, not `4/6` (correct: the question says simplest form, but there is no message saying "not simplest").
- **Low** `2^3 × 3^2` for P6 L2 2(a) is marked wrong (the key expects the five primes 2, 2, 2, 3, 3).
- **Low** `choice` keys are exact; `yes` would be wrong, but the control is a radio so it cannot be typed.

## 3. Skip, select, submit
Checked on all six lessons: any question opens from the numbered buttons; "Skip to next" and "Previous" move correctly; answers autosave and survive a reload; no solution or "The answer is" text exists in the DOM before Submit; Submit with blanks shows the confirm "N questions have no answer. Submit anyway? You will see the solutions for every question." with "Yes, submit" and "Keep working" (Keep working returns without submitting); after Submit every one of the 223 questions shows at least one worked step; the summary counts right/wrong/blank/self; inputs are locked; the submitted state survives a reload; "Change my answers and submit again" hides the solutions again; no console errors; no network request other than the page's own files. Paper-only items show "Do this on paper, then check your drawing against the answer shown on screen." with no text box, and show the correct-drawing figure after Submit where one exists (P4 L2 1c-mark number line with the X at 47 285, P6 L1 5-plan and 6c, P6 L2 2-tree and 6-plan); P6 L1 I1 and P6 L2 I1 (draw/list on paper) have a text solution only, which is fine.
- **Medium** After pressing Submit or "Submit anyway" the focus drops to `<body>` (the bar is re-rendered), so a keyboard or screen-reader user is not taken to the confirm or to the summary. Fix: move focus to the alertdialog / summary heading.
- **Low** The confirm counts self-check items that have no text box (all paper-only, and explanations the child did on paper) as "no answer", so a child who has finished every typed question still gets "8 questions have no answer" (P4 L1). Also the footer says "There is no score" but the summary says "11 of 30 marked questions are right".
- **Low** Footer text on every page: "Your answers stay in this browser only: nothing is sent anywhere." This is true today (the holiday build does not set `window.MI_SUBMIT`), but it contradicts SUBMIT-TO-TUTOR. The footer is static HTML in `index.html`; `sheet.js` adds its own "also sent to your tutor" line when sending is on, so the two would contradict. The optional "I checked it / I got it / not yet" ticks for self-check and paper-only items (D8 amended) exist only when sending is on, so they are not in this build. Before go-live the footer and the privacy wording must change together.
- **Low** The "similar one" practice (P4 L1 T2, P4 L2 3a/5a, P5 L1 1c/6b, P5 L2 3a/3b/4a/5a, P6 L1 1c/T1/3a, P6 L2 2c) shows the full answer and steps on the first wrong try ("Not yet" then "The answer is").
- **Low** No `noindex` meta on the pages; the data file contains all answers and solutions (design note Option A). Only matters at deployment (D2: enrolled families only).

## 4. Child-friendliness
- Reading load: average 24 to 40 words per question (P6 lowest, P5 L1 highest). Heaviest: P5 L1 3(a)/(b)/(c) repeat the six-clue riddle in full each time (122, 118 and 100 words); P4 L1 Investigation 115 words; P4 L2 I1a 85 words. These are the printed texts, so acceptable for the age, but 3(a) to 3(c) could show the clues once.
- **Medium** Hints that give the whole answer (against "kind and not giving the answer"): P4 L1 3(a) red/blue (`Find the factor pairs of 18: 1 × 18, 2 × 9, 3 × 6` is every factor); P4 L2 4(b) (lists all five numbers: "10 001, 10 010, 10 100, 11 000. Then 20 000"; the printed tip gives only two); P6 L2 T1(b) (all four pairs of 64); P5 L2 5(b) ("the other half is the $36 he had left"); P5 L2 6(a) hint says put 4 on top and 1 on the bottom. Nearly the answer: P5 L1 3(b), P6 L1 3(a) ("number in front of n is 4"), P6 L1 T4(b) rule, P4 L2 T1.
- **Medium** P5 L2 6(a) question text says "Type the sum as a fraction or a mixed number, like 5 1/2." 5 1/2 is the answer. Use another example (for instance `3 1/4`).
- Hints otherwise kind and sensible. Wrong answer text "Look at this one again", skipped "You skipped this one" are kind.
- Worked solutions: all correct. Minor: P5 L1 4(d) hint says "round to its first two digits" but the step rounds 806 to 810 (fine as an estimate, but not the stated rule); P4 L2 I2 mentions "by computer".
- Singapore wording: good ($, Mr Tan, interchange, bus numbers, take away, Mei/Ravi/Ali/Siti/Ben). No American spellings or words found by search. No coin or note figures.
- **P6 code blocks**: no iframe, no Scratch link, no `eval`, no "run it" instruction (the only "running" is P6 L1 4(b) "without running the code"). Programs are pictures drawn by the workbook's own `blocks()`. My hand traces: 4(trace) 7, 12, 17, 22; 4(a) 22; 4(b) 502; 6(a) 203 (say is after the loop); C3(a) 15; C3(b) 5050; 3-mod 0, 0, 2, 1, 0; 3-count 2, 3, 3, 3, 4; 3(a) 4; 3(b) 2; 6(a) 8 numbers; plan order E, C, B, F(A), D. All agree with `p6lib.run`, and the printed programs in `p6/content/l1.js` and `l2.js` match the online figures.
- **Low** Frames wrap awkwardly at 390 px: "x after loop 1: [ ] ; loop / 2: [ ]" (P6 L1 4-trace) and "Pattern 1 to 6, sticks: 4, [ ], / [ ] ..." separate a label from its box. Readable, but the boxes are not labelled.
- **Low** The numbered buttons run 1 to 38/36/44 and do not show the printed number ("3(b)"), so a child with the book open must read the question to find its place.

## 5. Accessibility
- Contrast, light and dark, 390 and 900 px, question, hint, answered, confirm, submitted, right, wrong, blank and solution states for all six lessons: every text is at least 4.5:1 except the white text on the red "set / change" variable blocks in the Scratch pictures (P6 L1 and L2), 4.38:1. **Low**: the colours come from the workbook's block drawing; darkening that red slightly fixes it.
- No horizontal scroll at 390 or 900 px on any of the 223 questions in any theme. Every figure text is at least 11 px on screen at 390 px and none is clipped. Tap targets are all at least 44 px. Input font is 22 px (no iOS zoom).
- Keyboard: every control is reachable; a visible 3 px outline shows on focus (light and dark); radios work with arrows and Space; the page is `lang="en"`, has one `h1`, a `nav` with labelled groups, `aria-current`, `aria-live` count, and each nav button has a text label plus a symbol (not colour only).
- **Medium** inputmode: number, list and box inputs use `inputmode="numeric"`. On an iPhone this keypad has no comma, no minus sign and no space, so "type the numbers with commas" (36 list items) and negative answers (P6 L1 2(a)/(b): `-4`) cannot be typed with it. I could not run iOS here; please test on a real iPhone/iPad. If confirmed this is High for P6 L1 2(b). Fix: `inputmode="text"` (or `decimal` + allow a switch) for list items and any box that can be negative; keep `numeric` for single positive numbers.
- **Low** 38 to 44 tab stops (the nav) come before the answer box, and there is no "skip to question" link.
- **Low** Radio groups and the "Box 1 ... Box 5" inputs have no group label tying them to the question or to which box is which.

## 6. Server marking parity
`make_keys.py holiday pN N` for all six lessons made keys; for each lesson I typed six answer sets per item in the real page (right, spaced/grouped/comma, units, +1, swapped/reversed, blank, and for text items several accepted wordings, a wrong string, upper case, trailing dot), submitted, and compared the page's mark with `mark.js` on the same strings: **0 differences in 1 338 comparisons** (223 items x 6). Self and paper items are `self` in both; the P6 "C1" items are `none` on the server and shown as "check yourself" in the page, as designed. **Low**: `make_keys.py` only treats a self-check as open (`none`) when its first step starts with "open", so P4 L1 1c-why, 5c-why, G5b; P4 L2 3b-why, G6; P5 L1 and L2 "pose" ("Puzzles will vary", "This question is open") are `self`, not `none`, unlike P6. The reports would count them as "checked on paper".

## 8. Private sources
No file under these three levels reads `docs/books/private_*`, the tutor guides, or `records.jsonl` (`grep`). I compared all question, hint, step and frame text with all of `docs/books/private_*` (about 495 000 seven-word shingles): only generic phrases overlap ("every multiple of 6 is also a multiple of 3", "when rounded to the nearest thousand, what is the smallest", "what fraction of the pizza is left", "which numbers have an odd number of"), and each of these questions is in the printed workbook source (`p4/content/lN.js` `workbook()`, which the build also checks).
